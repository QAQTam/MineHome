## 0. 结论

| 项 | 决策 | 备注 |
|---|---|---|
| 数据通路 | **BLE 直连**（唯一实时路径） | 云端 miotspec 通道拿不到实时值：spec access 全空、云 rpc 被拒（"bluetooth device does not support sending rpc"）；米家官方也只渲染兜底卡（getappconfig 无 fitting/njcuk 模板）→ 卡片必须自定义 |
| 卡片形态 | 首页**同尺寸**（148vp）专用渲染分支：一行四口格 | 不动首页网格布局；点卡片 → 既有 bindSheet 弹层加充电器详情分支 |
| 控制面 | **第一版只读** | spec TX（SpecTxState）下行方向未真机验证；下发 UI 必须用户显式确认后才做 |
| 刷新策略 | 进前台自动连一次 + 推送静默 30s 自动断开 + 手动刷新重连 | 常驻连接耗电且占设备唯一连接位；空载时设备本来就不推送，挂着无意义 |

## 1. 数据通路决策（写死进卡片）

```
真机屏幕（权威值）
   ↑ 显示一致
MineHome 卡片 ←── 0x001B 推送（AES-CCM 解密 → SPEC v2 帧 → port-info u32）
   ↑
BLE GATT 直连（登录流全链路已复刻：_work/ble_login.py run_login 可 import、60/60 闭环）
   ↑
@ohos.bluetooth.ble GATT client（本期新增，ArkTS 只做字节搬运）
   ↑
Rust napi（mible 派生 / CCM 解密 / spec 解析 / 端口解码——全部纯函数，本期新增导出）
```

- **快照兜底**：无 BLE 连接时，卡片显示上次会话的端口快照 + 时间戳（"快照 3 分钟前"）；从未连过显示"未连接"。
- **不做云端取数**：`get_properties`/`card_items` 对本设备返回不了实时值，卡片渲染直接走 BLE 分支，不浪费一次注定失败的云 rpc。

## 2. 卡片布局（148vp 内，一行四口格）

```
┌──────────────────────────────────────┐
│ [图标]  充电器           ●已连接/○未连 │   顶行：图标 40×40 + 名称 + 连接态徽标
│ ┌──────┬──────┬──────┬──────┐        │
│ │  C1  │  C2  │  C3  │  A   │        │   端口行：一行四列（标签 10f 灰）
│ │ 9.1V │  —   │  —   │ 9.0V │        │           电压行（14f 主色 / — 灰）
│ │ 1.1A │      │      │ 1.9A │        │           电流行（12f）
│ └──────┴──────┴──────┴──────┘        │
│ 总功率 20.2W · 快照 3 分钟前           │   状态行：总功率（有连接时）/ 快照时间 / 连接失败原因
└──────────────────────────────────────┘
```

- 每口功率不单列格内（太挤），**总功率 = Σ(V×I)** 放状态行；点开弹层看分口功率。
- 空载端口不推送（实测），显示 `—`；只有插着负载的口有新鲜值，与设备屏幕行为一致。
- 连接中：徽标转圈；登录失败：状态行显示"连接失败（0x23 拒绝/token 缺失）"等一句话。
- 品牌脱敏：卡片文案只用"充电器/端口 C1"，不出现米家/小米/酷态科字串（MineHome 守则）。

### 详情弹层（既有 bindSheet 加分支，只读）

- 顶部：总功率大字 + 连接按钮（连接/断开）+ 数据时间。
- 四口卡片：每口 V / I / P（功率=V×I）+ 端口名。
- 场景模式徽标：仅在收到 piid=5 推送时显示（AI/Apple/Single/Balance），未收到不显示。
- 不提供任何写入控件（等控制面决策）。

## 3. 字段映射表（port-info u32 → UI）

siid=2，piid→端口（spec `_work/spec_ad1204_v2.json`）：1=C1、2=C2、3=C3、4=A。

| 推送对象 | u32 LE 字节 | 解码 | UI |
|---|---|---|---|
| port-x-info | `[state][contract][I×0.1A][V×0.1V]` | V=x10v/10，I=x10a/10，P=V×I | 端口格两行 + 弹层功率 |
| scene-mode (piid 5) | int | AI/Apple/Single/Balance | 弹层徽标 |
| 亮屏时间 (piid 6)、协议控制 (7)、端口关闭 (8)、倒计时 (9~12) 等 | — | **本期不消费**（控制面相关，等拍板） | — |

实测锚点（三轮差分+屏幕对拍）：C1 缓降 b3=90/91 → 屏 9.0/9.1V；A 口 b2=19 → 屏 1.9A。**b1（协商上限）不用于 UI**（QC 族单位未定，样例 112）。

## 4. 连接生命周期

```
App 进前台（或用户点刷新/详情"连接"）
  → 设备亮屏？GATT connect(mac)               息屏时不广播，连不上 → 状态行提示"充电器亮屏后可连"
  → 订阅 0x0010 / 0x0019 / 0x001B notify
  → 登录流（镜像 _work/ble_login.py run_login，一字不改）：
      write 0x0010 = LE32(0x24)               # login start
      CMD 流 type=11 → appRandom(16B)         # 0000 00 0B 0100 → 等 ACK(01) → [0100]+16B → 等 ACK(00)
      ← type=13 devRandom                     # 设备 CMD start → 回 ACK(01) → 数据帧 → 回 ACK(00)
      ← type=12 devConfirm → Rust 校验 PASS   # HMAC(okm[0:16], dev‖app)
      CMD 流 type=10 → appConfirm(32B)        # HMAC(okm[16:32], app‖dev)；错则 0x23 后静默（每连接只评估第一个候选）
      ← 0x0010 裸 opcode 0x21 = 登录成功
  → 0x001B 推送：CMD start(2帧) → ACK(01) → 帧拼接（真帧 21B）→ ACK(00) → napi 解密解码 → 卡片更新
      （登录后首推 12~20s；插负载时秒级双推）
  → 推送静默 30s / App 进后台 / 手动断开 → gattClient.disconnect+close
```

连接纪律（沿用会话结论）：okm/appRandom/devRandom 必须同会话配套；每连接只试一个 appConfirm 公式（C）；sn/tid 每连接清零（Rust 全局槽在 open 时重置）。

## 5. 实现拆解

| 步骤 | 内容 | 产出 |
|---|---|---|
| R1 | napi 导出（mijia-napi/src/lib.rs）：`mible_derive(token,app,dev)→{okm,dev_confirm,app_confirm}`、`ble_session_open`（全局槽：MibleSession+SpecRxState）、`ble_spec_decode(frame_hex)→JSON`（解密→解析→siid=2 端口数组）、`ble_session_close`。**不暴露 TX** | 纯函数，mijia-core 已有实现，napi 是薄壳 |
| R2 | BleKit.ets 增 `ChargerGatt`：createGattClientDevice/connect/订阅/登录状态机/0x001B 组装/静默断开；回调 onState+onPorts | ArkTS 只做字节搬运，协议全在 Rust/_work 已验证 |
| R3 | Index.ets：DeviceCard 加充电器字段；DeviceCardView 分支渲染端口格；sheetBuilder 充电详情分支；前台连接/后台断开 | 复用既有色彩/圆角/按压规范 |
| R4 | 验收：cargo test 全绿（≥94）+ ArkTS BUILD SUCCESSFUL + 真机对拍（C1 插负载 → 卡片 9.xV/x.xA/≈10W 与屏一致；拔负载→30s 断开→快照标注） | 完成判据 2、3 |

风险与已知坑：token 须来自 device list 12B（真机验证 JsDevice.token 非空，缺则状态行报"token 缺失"）；设备息屏不可连；b1 不用；`ble_1b_session*.json` 真实 okm 勿入 git；`mijia-napi` 在开发机不参与编译验证（napi 薄壳须严格镜像既有写法）。
