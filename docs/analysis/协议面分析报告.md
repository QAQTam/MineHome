## 1. App 分层架构

米家 Android 端本质是一个 **宿主 + 多引擎插件 + 多协议网络栈** 的三层结构：

```
┌─────────────────────────────────────────────────────────────────┐
│ UI 层：newui(742)/mainpage/fragment + Compose (androidx.compose) │
│   设备卡片、首页、家庭/房间、场景编辑器                              │
├─────────────────────────────────────────────────────────────────┤
│ 插件层（三种运行时）：                                             │
│   RN 插件 miot.plugin.*  ←  assets/builtin_bundles + rn_plugins │
│   Hermes 小程序 *.hbc     ←  maml/card/spec (specprofile.hbc)   │
│   Hybrid H5              ←  WebViewJavascriptBridge             │
│   插件经 NativeBridge 拿到设备控制、TCP/UDP/BLE socket 能力         │
├─────────────────────────────────────────────────────────────────┤
│ 核心服务层 core/server（可跨进程 AIDL：ICoreApi/ILocalControl）：   │
│   账号 internal/account  →  com.xiaomi.accountsdk (XMPassport)  │
│   网络 internal/api      →  MijiaCookie + Crypto.RC4/HTTPS      │
│   蓝牙 internal/bluetooth→  GATT 通道 + MiBeacon 解析 + 三种安全认证│
│   设备设备仓 device/api   →  DeviceApi (/v2/home/device_list...) │
├─────────────────────────────────────────────────────────────────┤
│ 协议传输层（多栈并存）：                                           │
│   miio UDP      : libmiio.so + JNIBridge (54321, 0x2131)        │
│   localcontrol  : liblocalcontrol.so (lan_dm_* 发现+RPC)        │
│   centralclient : libcentralclient.so (mDNS+TLS 长连接)          │
│   BLE           : libblecipher.so + inuker bluetooth library    │
│   推送           : MiPush XMPushService + 5 厂商通道 + MiConnect  │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 账号与登录链路

来源：`com/xiaomi/accountsdk/account/URLs.java` + `XMPassport.java`（本包逐行确认）。

```
1. GET https://account.xiaomi.com/pass2/config        ← 拿公钥/配置
   GET https://account.xiaomi.com/pass2/user/status   ← 用户状态(2FA)
2. GET https://account.xiaomi.com/pass/serviceLogin
   （带 sid=xiaomiio、_json=true；判断是否已登录，返回 _sign/qs/captcha 预置参数）
3. POST https://account.xiaomi.com/pass/serviceLoginAuth2   ← 真正的密码登录
   form: user(加密后的账号) / hash(MD5 大写密码) / _sign / qs / callback /
         sid=xiaomiio / _json=true / (验证码 captCode、2FA 走 loginStep2)
4. 响应 JSON: userId / passToken / ssecurity / serviceToken / nonce / psecurity
5. 之后所有 io.mi.com 请求用 serviceToken 作 Cookie；ssecurity 用于请求体加密签名
6. 刷新: /pass/serviceLogin (带 passToken) 或 /login/passtoken/refresh
7. 登出: /pass/logout
```

要点：
- **sid 必须是 `xiaomiio`**（IoT 服务），不是 `passport` 或 `mico`；`MijiaCookie` 里 `r1d.o000oOoO()` 取的就是它。
- 登录响应里的 **`ssecurity` 是 16 字节 base64**，它是后续云端 API RC4 加密的根密钥，也是推送到设备的本地凭据派生根。
- 第三方登录（QQ/微信）走 `/pass/sns/login/check` + oauth2。

## 3. 云端 API 面（api.io.mi.com）

来源：`DeviceApi.java`、`MijiaCookie.java`、`CoreApiStub.java`、`strings_all.txt`（全部为本包内出现的路径）。

### 3.1 请求模型

```
POST https://api.io.mi.com/app/<path>
Cookie: serviceToken=<token>; yetAnotherServiceToken=<token>; userId=<uid>;
        cUserId=<uid>; locale=zh_CN; timezone=GMT+08:00; timezone_id=Asia/Shanghai;
        is_daylight=0; dst_offset=0; channel=<MIUI_APP|APP>; countryCode=CN;
        PassportDeviceId=<did>
Body:   {"params":{...}}          ← Crypto.RC4 模式下整个 JSON 用 RC4 加密
Header: X-XIAOMI-PROTOCAL-FLAG 等
```

`Crypto` 枚举（`core/entity/net/Crypto.java`）：`NONE / RC4 / HTTPS` —— RC4 模式即经典的 ssecurity 派生密钥加密体（与开源 miot-python 一致：nonce→signedNonce→RC4 key，`pa:` 前缀）；签名计算部分在混淆类 `_m_j/rle.OooO00o()` 内（jadx 复杂方法跳过），可按 miot-python 公开实现对照复刻。

## 4. miIO UDP 协议（手机 ↔ 设备/网关 直连）

来源：`com/xiaomi/miio/OooO00o.java`(=MiioLocalAPI)、`JNIBridge.java`、`libmiio.so`（全部本包确认）。

```
端口: UDP 54321（OooOo0(): datagramSocket.send(..., 54321)）
发现: mDNS _miio._udp.local.（strings_all.txt 确认）+ 直接 IP 广播
Hello: token = "ffffffffffffffffffffffffffffffff"（32 字节 ASCII f，MiioLocalAPI 常量）
报文头: magic = 0x2131（line 314: order.put("2131")）
```

报文格式（与公开 miIO 规范一致，本包 `MiioMsg{did, stamp, token, message}` 结构吻合）：

```
┌ magic(2B)=0x2131 ┬ len(2B) ┬ stamp(4B,秒级) ┬ checksum(16B) ┬ payload(变长) ┐
   hello 包: token 域全 0xFF，payload 空，stamp=0
   命令包:   key = MD5(token)；payload = AES-128-ECB(JSON)；
             checksum = MD5(key + stamp + payload + key)
```

- `JNIBridge.encrypt/decrypt` 在 `libmiio.so`（AES_set_encrypt_key/AES_cbc_encrypt 符号可见），另有 `hencrypt/hdecrypt`（网关加密变体）与 **`smencrypt/smencryptpk`（国密 SM4，蜂窝设备用）**。
- 常用方法字符串（本包确认）：`miIO.info`、`miIO.handshake`、`miIO.get_subdev_list`、`get_prop`、`miIO.event`、`miIO.config_router_safe`、`miIO.ota_install`、`miIO.zb_end_provision`、**`miIO.get_central_link_passcode`**。
- 本地未绑定/陌生设备只能用 hello 拿到 token checksum，真正控制必须持有 token（云端 `/v2/home/device_list_page` 返回每个设备的 `token` 字段——这也是为什么离线控制前必须先登录过一次）。

## 5. 离线控制三路径（重点）

### 5.1 WiFi 设备 / 老网关：miIO UDP 直连

条件：手机与设备同 LAN，app 本地缓存了该设备 token。
流程：mDNS `_miio._udp.local.` 或 IP 扫描发现 → hello → token 校验 → `get_prop`/spec RPC（`/home/rpc/` 的本地等价物）→ 直接控制。断云不影响。

### 5.2 多模网关子设备（Zigbee/蓝牙 Mesh/PLC）：LocalControl SDK

来源：`com/xiaomi/miot/localcontrolsdk/LocalControl.java` v0.0.27 + `liblocalcontrol.so`。

```
LocalControl.createLocalControl()          ← 加载 liblocal_control_interface.so
  ├ startDiscovery(intervalMs) / oneShotDiscovery(did, ?, checkPerm)
  ├ getDeviceList(cb)                      ← lan_dm_get_lan_device_list
  ├ getSubdeviceList(did, ?, MESH|PLC|ZIGBEE|BRIDGE|MATTER, offset)
  │    ← liblocalcontrol.so 内拼 {"method":"miIO.get_subdev_list",
  │       "params":{"type":"...","online":true,"offset":0}} 走 UDP
  ├ sendRPC(did, token, method, timeoutMs) ← lan_dm_send_rpc (加密)
  └ stopDiscovery()
```

so 内部函数：`lan_dm_create / lan_dm_init_device_cipher（按设备加密）/ d0_udp_open / udp_net_sendto / lan_dm_start_peroid_discovery`。这就是"离线控网关+子设备"的主通道：**app 把网关当作一台 miIO 设备，用它的 token 走 UDP，网关内部再翻译成 Zigbee/Mesh/PLC**。

### 5.3 米家中枢网关（Central Gateway）：mDNS + TLS 长连接

来源：`com/xiaomi/miot/centralclientsdk/` v0.2.9 + `libcentralclient.so`（全部本包确认，协议细节完整还原）。

**发现**
```
mDNS 服务类型: _miot-central._tcp.
TXT "profile" = base64(CentralProfile, ≥23 字节):
  [0]    flags: bit0 fixedRole, bit2 isOnline, 高4位 version
  [1..8]  did (big-endian → BigInteger)
  [9..16] groupId（字节倒序存放）
  [17..19] priority
  [20]    低4位 linkType(0=eth,1=wifi5G,2=wifi2.4G), 高4位 role(1=primary,2=secondary,3=limited,4=controller)
  [21]    rssi (signed)
  [22]    bit0 suitIDM, bit1 suitMQTT
有效性校验（MdnsClient.getValidCentralDid）:
  SHA1( ownerUid + "central_service" + homeId ) 的前 8 字节 == groupId
  且 role==primary 且 suitMQTT；owner 账号直接可用，共享家庭需 version>0
```

**连接与鉴权**
```
CentralClient.start(deviceType=1 Phone, ...) → native libcentral_client_interface.so
  → TLS 长连接（内嵌 BoringSSL；手机用客户端证书）
客户端证书获取: 通过 OTProxy 云中继 —— _sync.device_get_cert 请求手机拿证书，
  _sync.lv2_ca_cert 下发 L2 CA；_sync.get_homeroom_info 同步 uid/owneruid/homeid
（OTProxy = 云端转发通道：手机与中枢不在同一 LAN 时也能远程连中枢）
配对凭证: miIO.get_central_link_passcode（中枢上生成，手机输入/扫码获取）
```

**通道模型**：topic 化的 API/broadcast
```
callAPI(topic, payload, timeout) / registerAPI(topic, handler)   ← RPC
sendBroadcast(topic, payload) / registerBroadcast(topic, handler) ← 事件
onCentralConnected(did) / onCentralDisconnected()
```
即：**中枢网关把"云端 io.mi.com 的语义"原样搬进了局域网** —— app 离线时把 `/app/xxx` 请求改投到 TLS 通道上的中枢，由中枢转发给子设备（中枢 suitIDM 表示支持这套 IDM API）。这正是米家"中枢网关离线全屋可控"的实现。

### 5.4 BLE 直连与 Mesh 子设备（无网关）

- MiBeacon 广播：`MiotBleAdvPacket` 解析 0xFE95 服务数据；加密广播用 beaconkey（`/v2/device/blt_get_beaconkey`）。
- BLE 配网三种安全模式（`core/server/internal/bluetooth/security/`）：`pskauth`（老 PSK）、`securitychipauth`（安全芯片，`BleMeshRegisterConnector/BleMeshLoginConnector`）、`combo`（BLE 传 WiFi 凭据，`BleComboWifiConfig`）。
- Mesh 子设备：bindkey（`/v2/user/get_bindkey`）→ `/v2/blemesh/*` 云端配网；控制走 mesh key 加密的 mesh PDU，经手机 GATT Proxy（0xFE95）或网关代理。断云时 mesh key 已缓存在本地，手机可直连 mesh 网络发 PDU。

### 5.5 离线决策总结

| 场景 | 通道 | 前置条件 |
|---|---|---|
| WiFi 单品 | miIO UDP 54321 | 本地缓存 token |
| Zigbee/网关子设备 | miIO UDP → 网关 → Zigbee | 网关 token |
| 蓝牙 Mesh 子设备 | GATT Proxy / 网关 mesh 代理 | bindkey + mesh key 缓存 |
| 中枢网关全屋 | mDNS+TLS topic API | 客户端证书 + passcode 配对过一次 |
| 全离线且从未登录 | 无 | 任何控制都拿不到 token |

## 6. 推送与状态同步

## 8. ohos-rs + ArkTS 落地映射建议

| 米家 Android 组件 | 鸿蒙侧对应 | 放哪层 |
|---|---|---|
| XMPassport 登录 | Rust: reqwest 实现 serviceLoginAuth2 + 表单参数 | ohos-rs（纯 Rust，无 UI） |
| MijiaCookie + Crypto.RC4 | Rust: 拦截器统一加 Cookie + ssecurity RC4 加密体 | ohos-rs |
| miIO UDP (0x2131) | Rust: tokio UdpSocket + MD5/AES-128-ECB（`md-5`/`aes` crate） | ohos-rs |
| LocalControl SDK | Rust: UDP 发现 + lan_dm 协议（`miIO.get_subdev_list`/sendRPC） | ohos-rs |
| CentralClient | Rust: mDNS（`mdns-sd` crate）+ rustls（客户端证书）+ topic 分发 | ohos-rs |
| BLE GATT/Beacon 解析 | ArkTS `@ohos.bluetooth.ble` + Rust 解密（beaconkey） | ArkTS 采集，Rust 解析 |
| MiPush / 状态同步 | 鸿蒙 Push Kit + 自建 WebSocket 长连 | ArkTS + ohos-rs |
| 设备页 | ArkTS 组件 + spec JSON 驱动渲染（对应 specprofile） | ArkTS |
| 插件沙箱（RN/hbc） | 建议不做完整插件系统，直接用 spec v2（`si/siid/piid`）统一渲染 | ArkTS |

建议的最小可行顺序：
1. **登录 + device_list**（拿 token/ssecurity/spec）→ 已有 device_list 即可渲染设备。
2. **miIO UDP 直连**（WiFi 设备离线控）——协议最简单、收益最直观。
3. **云端 RPC `/home/rpc/<did>`**（在线控全部设备）。
4. **网关子设备**（LocalControl 的 `miIO.get_subdev_list` + 网关 RPC）。
5. **中枢网关 TLS**（最后做，证书体系最复杂）。
6. BLE 建议先支持 MiBeacon 解析展示，控制类 mesh 放后。
